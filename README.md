# Mikhail — selected work

A static, bilingual portfolio with four separate directions: Virtual Try On, Food Design, Jewelry & Watch, and Furniture. The home page is an interactive exhibition of four visual worlds. The category pages contain 93 approved images: the previous 27 plus 66 new stills grouped around 40 new product references. Photographs are always fitted in full.

## Visual design

Warm alabaster, graphite and a vermilion accent support large editorial typography. Each home chapter has its own atmosphere, an approved final photograph and the exact original product photograph. Four keyboard-accessible tabs change the exhibition. Both photographs are decoded before a chapter appears; rapidly switching tabs cannot insert an outdated image. Category previews form four aligned rows with two photographs each.

The spatial exhibition uses CSS perspective and a reflective sculpture rendered directly with WebGL. Photo planes and sculpture share one eased pointer pose: entry ramps in over 240 ms, exit returns gently to neutral, and animation stops when settled, offscreen or hidden. Idle time never becomes a large first-frame timestep. Prints keep their stacking order. The canvas is capped at 540 pixels on its longest side. No 3D library, downloaded model or perpetual render loop is required. Photographs and links remain usable without WebGL.

Cross-document navigation uses progressive [CSS View Transitions](https://developer.chrome.com/docs/web-platform/view-transitions/cross-document). Browsers without support use ordinary navigation. Reduced motion disables transitions, scroll animation, reveal motion and pointer parallax. Category pages include sticky series navigation, a strip of original references and a fullscreen viewer. Choose comparison, result or reference; use previous/next controls, arrow keys and Escape. Closing the viewer restores focus. Mobile layouts retain all four sections, full photographs and comparison tools.

Small accent text uses a darker red than the large display typography. Small text colors meet 4.5:1 against the paper background; large orange display text meets 3:1. Page shells share a resource version to prevent old scripts from being combined with new styles. Each direction has its own social preview.

## Preview

```bash
python -m http.server 8000 --bind 127.0.0.1
```

Open `http://127.0.0.1:8000/`.

The landing page includes a static selection and direct links before JavaScript runs. The script-enhanced gallery replaces that selection when the portfolio data loads. The project discussion form is served by Formspree; its public endpoint is configured in `js/site-config.js` and its fallback remains a normal HTML form submission.

Commercial contact links in the page headers, footers, case studies and image viewer open `contact.html`. Direct email remains available on that contact page. Valid campaign fields and the opaque reference also reach contact links created after page initialization, including the viewer; the selected work stays attached to the inquiry. Only a confirmed positive form response emits `brief_submit_success`, which is configured as a GA4 key event. Contact clicks do not count as successful inquiries.

## Content

- `index.html`: landing page and four direction links.
- `vton.html`, `food.html`, `jewelry.html`, `furniture.html`: dedicated portfolio sections.
- `css/editorial.css`, `js/editorial.js`: presentation and reference/result viewer.
- `js/spatial.js`: WebGL sculpture, pointer depth, progressive reveals and scroll progress.
- `js/image-sizes.js`: original dimensions, used to reserve image space before loading.
- `js/curated.js`: the original approved selection and section definitions.
- `js/site-config.js`: public GA4, Clarity and Formspree project identifiers. It contains no secret keys.
- `js/analytics.js`: consent UI, provider loading and the allowlisted portfolio events. Neither analytics provider loads until a visitor accepts; declining is remembered in that browser. Advertising and ad personalization stay disabled.
- `js/conversion.js`, `css/conversion.css`: bilingual service/contact sections and layouts for the three self-initiated case studies, contact page and privacy notice.
- `contact.html`, `privacy.html`, `case-food-campaign.html`, `case-fashion-images.html`, `case-furniture-scenes.html`: the inquiry form, privacy notice and portfolio case studies. The three studies are self-initiated examples, not client engagements.
- `scripts/campaign_link.mjs`: generates a link with allowlisted campaign fields and a new random 128-bit reference. Example:

  ```bash
  node scripts/campaign_link.mjs --page food.html#series-1 --source outreach --medium email --campaign brand_oct26
  ```

  The script prints the link and never writes a lead mapping. Store any reference-to-lead association only in the private, encrypted CRM. Do not put names, email addresses, company names or other personal data in a campaign URL. A visit or click can be generated by a security scanner and does not prove that a person read the message.
- Analytics records broad page and work interactions after consent. It does not receive form contents, names, emails or product links. Contact clicks and successful form submission are engagement events, not evidence of a reply, sale or paid conversion.
- `js/portfolio-additions.js`: the 66 approved additions, bilingual copy, series and links to lossless originals. It must load after the original selection and before the viewer.
- `assets/curated/`: selected final WebP images, responsive previews and original product reference photos. `originals/` contains the approved full-resolution PNG files.
- `scripts/build_category_pages.ps1`: keeps the four category page shells in sync.
- `scripts/build_image_sizes.py`: reads original image dimensions with Pillow, without changing the photographs. Run after changing the selected assets.
- `scripts/build_reference_previews.py`: creates smaller WebP display copies of the source photographs for the site. Original PNG files stay untouched and can be opened from the reference viewer. These display copies only resize and encode the photograph; no retouching or compositing is performed.

## Verification

```bash
node tests/content.mjs
node tests/spatial-motion.mjs
node tests/analytics.mjs
node tests/contact.mjs
node tests/campaign-link.mjs
node scripts/build_category_pages.mjs --check
python scripts/build_responsive_previews.py --check
python scripts/build_image_sizes.py --check
python tests/media-metadata.py
python scripts/check_media_metadata.py
```

The content check covers the approved selection, series coverage, references, dimensions, local links and resource versions. The analytics check covers consent gating, provider queues, sanitized URLs and event fields. The motion test executes the actual scene script with controlled frame timing, checking edge entry, exit/re-entry, restart after idle, CSS/WebGL synchronization, visibility, reduced motion, touch and the absence of an idle render loop. Browser inspection is still required for visual changes.

When releasing CSS or JavaScript changes, update the shared resource version in the page shells and run `node scripts/build_category_pages.mjs` to regenerate the category pages. The generator reads the category resource version from `index.html`; `scripts/build_category_pages.ps1` is a wrapper for it. Commit directly to the configured publishing branch.

The public repository contains the website and selected visual assets. Internal production records and review reports are maintained separately.

Legacy `work.html` and `case.html` links redirect to the landing page. Public media and reachable history were sanitized before this release. Never restore an old binary asset or diagnostic board without checking its metadata and visible annotations. Private production reports and history backups belong outside this repository. Two planned animated loops are not included in the still-image release.
